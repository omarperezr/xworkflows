# A user's git hook keeps its name and its place

Goal: G1

Spec: docs/superpowers/specs/2026-11-13-hook-line.md

## Global Constraints

- "Una línea en el hook del usuario"
- "Migrarlos solo"
- `install` never renames, moves or replaces a hook it did not write. The only change to a user's file is one marked line, added with a yes and removed whole by `uninstall`.
- Node standard library only. Every file install writes is a manifest piece or a text the installer generates and records, as the hooks are today.
- The hook texts are POSIX `sh`: no bash-only syntax.

## Tasks

### Batch 1: `hook-line-1`

Estimated code lines: about 250, in one file. It cannot be cut smaller: the install, doctor and uninstall of a hook must change together or a project is left with a hook one of them does not understand.

**T1: install adds one marked line to a user's hook in place of renaming it; doctor, uninstall and the migration of old installs follow** (spec sections 2 and 3)
- Files: `bin/xworkflows.mjs`, `bin/xworkflows.test.mjs`
- Role: implement
- The tests of spec section 3 come first and are seen failing. The tests of today's chaining that no longer hold are rewritten to the new rule, not deleted: each keeps what it protected (the user's hook runs, its failure stops the push, uninstall restores it byte for byte).
- Done: `node --test bin/xworkflows.test.mjs` passes.

**T2: the documents say what install does with a hook that is already there** (spec section 2)
- Files: `README.md`, `docs/design.md`, `docs/gaps.md`
- Role: implement
- Only the sentences about an existing git hook change. The README sentences that `skills/day-one.test.mjs` pins stay word for word.
- Done: `git grep -n "before-xworkflows" -- README.md docs/design.md docs/gaps.md` prints only lines about installs made before this change, and `node --test skills/day-one.test.mjs` passes.

## Review Focus

- A user's hook is the user's: after `install` and `uninstall` it must be byte for byte what it was, and between them it differs by one line only.
- The push check must not be skipped: a user's hook that exits early, reads its standard input or fails must not let a push through unjudged, and a project without xworkflows must not be broken by the line.
- The user's `pre-push` must still receive the pushed refs on its standard input.
- An install made the old way must end in the new form or stay fully working: never half of each.
