# safe-db closes its open gaps; install drops a renamed hook and reads big repositories

Goal: G1

Spec: none; the design is in the cards P-211, P-218 and P-206 of docs/PENDING.md and in the owner's answers below.

## Global Constraints

- "luego haz A luego C luego B y D en paralelo" (group A is this plan).
- Node standard library only. Broken input lets the call through. Hook logic stays a pure `decide(ev, ctx)` with its test beside it.
- Every installed file is a manifest piece: after T1 and T2, `node bin/xworkflows.mjs pack --check` prints nothing.

## Owner's answers

Grill of 2026-11-20, each the recommended option:

- P-211: all 13 open gaps go in. One general rule covers every command that writes or deletes a database file (the extensions safe-db already uses: `.db`, `.sqlite`, `.sqlite3`; no new config key); each other gap gets its own rule.
- The new rules give the verdict safe-db gives today: ask in the main session, deny in a subagent.
- Includes (`\i`, `\ir`, `\include`, `.read`, `source`) inside a file safe-db reads are followed up to 5 levels, with a cycle guard; an include that cannot be read lets the call through with a warning.
- P-218: ~~automatic~~ changed after the risk review of 826831d (finding 6: a stale copy of the package that does not know a newer hook would unwire it). The owner: "Explicit list + pack check (Recommended)". The manifest lists the hook ids it retired; install removes our settings entries of a listed id, and their module when its hash matches the record; a module changed locally is kept and reported. `pack --check` fails when a hook id of the manifest at `HEAD` is missing from the new manifest and not on the retired list. Uninstall tells our entries by id, not by event alone.
- P-206: every call in `bin/` whose output grows with the repository (file lists, logs) goes through one helper with a 256 MiB buffer; a failure there warns instead of passing silently. Calls with short output stay as they are.

### Fix round 2

Confirmation of 05bd2a7: one blocking finding, proven red; one ask-owner; two pending, which the owner put in this round: "Both in this round (Recommended)".

Possible design error in `hooks/core/safe-db.mjs` `decide` (the `xargs rm` feed)
Root cause: round 1 answered a false alarm with an allow list of the stages that feed names (`find|ls|echo|printf`); in a safety brake an allow list opens a hole for every command not on it. Alternative design: a block list, so only a stage that reads content (a database client, `cat`) stops feeding. The owner: "Redesign: flip the list (Recommended)".

Possible design error in `hooks/core/safe-db.mjs` `decide` (include folder)
Root cause: round 1 gave every file of `sqlFiles` the `-f` folder rule, but psql resolves `\ir` from the cwd for a script read on stdin. Alternative design: `sqlFiles` marks each name `<` or `-f`; `<` names scan from the working folder, as piped files already do.
