# safe-db closes its open gaps; install drops a renamed hook and reads big repositories

Goal: G1

Spec: none; the design is in the cards P-211, P-218 and P-206 of docs/PENDING.md and in the owner's answers below.

## Global Constraints

- "luego haz A luego C luego B y D en paralelo" (group A is this plan).
- Node standard library only. Broken input lets the call through. Hook logic stays a pure `decide(ev, ctx)` with its test beside it.
- Every installed file is a manifest piece: after T1 and T2, `node bin/xworkflows.mjs pack --check` prints nothing.

## Owner's answers

Grill of 2026-11-20, each the recommended option:

- P-211: all 13 open gaps go in. One general rule covers every command that writes or deletes a database file (the extensions safe-db already uses: `.db`, `.sqlite`, `.sqlite3`; no new config key); each other gap gets its own rule.
- The new rules give the verdict safe-db gives today: ask in the main session, deny in a subagent.
- Includes (`\i`, `\ir`, `\include`, `.read`, `source`) inside a file safe-db reads are followed up to 5 levels, with a cycle guard; an include that cannot be read lets the call through with a warning.
- P-218: automatic. Install removes our settings entries whose hook id the manifest no longer has, and their module when its hash matches the record; a module changed locally is kept and reported. Uninstall tells our entries by id, not by event alone.
- P-206: every call in `bin/` whose output grows with the repository (file lists, logs) goes through one helper with a 256 MiB buffer; a failure there warns instead of passing silently. Calls with short output stay as they are.
