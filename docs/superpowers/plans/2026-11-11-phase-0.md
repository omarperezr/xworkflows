# Phase 0: thin slice through four tools — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pass proof 6 of section 10 — Claude Code denies a forbidden write in a real session (recorded `deny` answer as evidence); Codex, Cursor and Gemini CLI adapters pass tests against fixtures built from their official docs, labeled `documented`.

**Architecture:** One pure core (`hooks/core/design-first.mjs`) decides allow or deny on a normalized event. One runner (`hooks/run.mjs <tool> <hook>`) reads stdin, calls the tool's adapter to normalize, writes skill marks, calls the core, and answers in the tool's form; any error lets the call through. A hand-written `sandbox/` holds the layout of section 6.1 for all four tools; it is where the real Claude Code session runs. No installer, no manifest, no `tiers.json`.

**Tech Stack:** Node (v26.13.0 on the build machine), standard library only, ESM `.mjs`, tests with `node --test`.

**Spec:** `docs/design.md` (approved 2026-11-10). Sections used: 2, 6.1, 7.1, 7.2, 7.3, 7.6, 7.7, 10 (proof 6), 11, 12.

## Global Constraints

- No dependency, no `package.json`. Node standard library only (section 2, 6).
- Every hook: broken input lets the call through with a warning on stderr; a hook never traps an agent (7.2).
- Escape variable `XWORKFLOWS_FREE`: when set, the hook allows and writes one stderr line naming the hook (7.2, reference-coupling constant).
- Names and paths come from `<root>/.xworkflows/config.json`; built-in defaults are the reference values: `owner` = `"the owner"`, `paths.specs` = `"docs/superpowers/specs"`, `paths.plans` = `"docs/superpowers/plans"` (7.7).
- Product constants (7.7, reference-coupling): skill name `grill`; headings `Questions for the owner` and `Owner's answers`; a question is a line ending in `?`; state file prefix `xwf-`; mark command `node .xworkflows/mark.mjs <skill>`.
- Fixture labels: `recorded` (only from a real session), `documented` (built from an official page; carries `source` URL and `read` date), `not confirmed` (a shape the official pages do not give). Never `recorded` for a tool that was not run (section 11).
- Cursor's hook input carries `user_email`. Adapters never store or print it; fixtures set it to `null` (7.2).
- **Privacy, before any commit:** `docs/reference-coupling.md` and `docs/measure-tokens.py` name private paths and must not enter a repo that will be public. They are git-ignored in Task 1, before the first commit. Before every commit, both of these print nothing:
  - `git ls-files docs/reference-coupling.md docs/measure-tokens.py`
  - `git grep -nE '/Users/[a-z]|-Users-[a-z]'` (the `[a-z]` keeps this plan's own text from matching)
- Git (7.6): add files by explicit path, never `git add .` or `-A`. No commit names an AI as author or co-author: no `Co-Authored-By` line. Push only when the owner says so.
- Full test command: `node --test` from the repository root (finds every `*.test.mjs`).

## Review Focus

1. **A session id with path characters** (`../x`, `a/b`): the mark file must stay inside the state folder. Test in Task 2.
2. **Cursor blocks on any answer that is not valid JSON**, and Gemini requires stdout to be JSON only: the allow answer on broken input must still be the tool's JSON. Test in Task 4.
3. **Paths in every form**: absolute, relative, Windows backslashes, and a path outside the root (`../docs/superpowers/specs/x.md`) that must not match. Test in Task 1.
4. **Recorded fixtures leaking the home folder** (`cwd`, `transcript_path` carry it, also in the dashed form Claude Code uses for project folders). Test in Task 2.
5. **A mark from another session does not count.** Test in Task 2.
