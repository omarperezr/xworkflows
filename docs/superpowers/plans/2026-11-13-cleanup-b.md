## Review Focus

- `install` and `uninstall` write into a user's project: nothing of the user's is written over or removed without a question, and what install recorded is what uninstall takes back. A second install changes nothing.
- `doctor` never throws; a line it prints for a problem names a command that is right for that project's settings.
- The checks decide whether a push passes: a change here must not let a commit through unjudged, nor refuse a correct push.
- The hooks run before every tool call of every project: they must not deny a correct call, and they must stay fast.
- The scanner and the research write a project's rules: a file or a sentence that drops out silently is a rule the project never gets.
- The proof folder spends money only through the harness; no test calls a model.
