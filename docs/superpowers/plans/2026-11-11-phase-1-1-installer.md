# Phase 1.1 Installer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command installs xworkflows' existing pieces into a Claude Code project without harming its configuration, `doctor` proves the install works, and `uninstall` takes it back out.

**Architecture:** `manifest.json` lists every piece with per-file sha256 hashes; `pack` keeps it current. `bin/xworkflows.mjs` (one file, Node standard library) reads the manifest, plans every write against the target repository, asks its questions, then writes files, merges shared files, and records everything in `.xworkflows/installed.json`. `doctor` and `uninstall` work only from that record.

**Tech Stack:** Node 22+ standard library (`node:fs`, `node:path`, `node:crypto`, `node:child_process`, `node:readline`, `node:test`), git.

**Spec:** `docs/superpowers/specs/2026-11-11-phase1-1-installer-design.md` (approved 2026-11-11). It builds on `docs/design.md` sections 4 to 6.2. Read both.

## Global Constraints

- Node standard library only, no dependency, no build step, no network call in any command. `"engines": { "node": ">=22" }`.
- The CLI is one file, `bin/xworkflows.mjs`. Its tests are `bin/xworkflows.test.mjs`, run by `node --test` from the repo root, driving the CLI with `spawnSync` against temporary git repositories.
- Exit codes: 0 ok; 1 fail or refused; 2 usage error or a tool not yet supported. `--tool <x>` other than `claude` prints `not yet: <x> comes in a later phase` and exits 2.
- Every command needs a git repository; the target is `git rev-parse --show-toplevel` of the current folder. Outside a repo: exit 1.
- The CLI never runs `git add`, `git commit` or `git push`, and never overwrites a file it did not write.
- No timestamps and no machine paths in anything it writes. JSON is written as `JSON.stringify(value, null, 2) + "\n"`.
- Every sha256 is taken over the text with `\r\n` replaced by `\n`.
- Hook command form, exactly: `node "$(git rev-parse --show-toplevel)/.xworkflows/hooks/run.mjs" claude <hook-id>`.
- Build rules (design 7.6): work on branch `phase-1-1-installer`; add files by explicit path, never `git add .` or `-A`; no AI author or co-author line in any commit; no push.
- Before every commit both must print nothing: `git ls-files docs/reference-coupling.md docs/measure-tokens.py` and `git grep -nE '/Users/[a-z]|-Users-[a-z]'`.

## Review Focus

1. The project's own `settings.json` entry uses the same matcher as ours (`Write|Edit|MultiEdit|Bash`) with its own command: ours is appended as a separate entry; theirs is untouched (Task 4).
2. `CLAUDE.md` or `AGENTS.md` without a trailing newline: the import line and the block start on their own line, and a second install changes nothing (Tasks 4 and 5).
3. The CLI is run from a subfolder of the repository: everything lands at the top level (Task 3).
4. `doctor` runs inside a Claude Code session, where `CLAUDE_PROJECT_DIR` and possibly `XWORKFLOWS_FREE` are set, and the project path has a space: the probe still tests this install and still expects `deny` (Task 6).
5. `installed.json` is corrupt (not JSON): `install` exits 1 and writes nothing; `doctor` fails; `uninstall` exits 1 (Tasks 3, 6, 7).

### Task 3: `install`: files and the record

**Files:**
- Modify: `bin/xworkflows.mjs`, `bin/xworkflows.test.mjs`

**Interfaces:**
- Consumes: `hash`, `digest`, `readManifest` (Task 2); `repo`, `cli` (Task 1).
- Produces: `.xworkflows/installed.json` with keys in this order, each always present (empty `[]`/`{}` when unused): `xworkflows`, `tools`, `pieces`, `files`, `merged`, `blocks`, `imports`, `created`, `declined`, `kept`, `renamed`. `files[<target path>] = { piece, sha256 }`. `kept` is a list of target paths whose project version was kept (Task 5). `tiers.json` is recorded with `"piece": "installer"`.
- Produces, in `bin/xworkflows.mjs`: `plan(manifest, root, record) -> { writes: Array<{ path, text, piece }>, merges: [...], questions: [...] }` and `apply(plan, root)`. Later tasks add to `merges` and `questions`.

Placement (spec 5.2):

| Source | Target |
|---|---|
| `skills/<id>/<f>` | `.claude/skills/<id>/<f>` |
| `agents/<id>.md` | `.claude/agents/<id>.md`, the front-matter line `tier: <t>` replaced by `model: <tiers.claude[t]>` |
| `hooks/mark.mjs` | `.xworkflows/mark.mjs` |
| `hooks/adapters/<tool>.mjs` | `.xworkflows/hooks/adapters/claude.mjs` only for `claude`; other adapters are not written |
| other `hooks/**` | `.xworkflows/hooks/<same path below hooks/>` |
| `tiers.json` | `.xworkflows/tiers.json` |

### Task 4: `install`: merges into shared files

**Files:**
- Modify: `bin/xworkflows.mjs`, `bin/xworkflows.test.mjs`

**Interfaces:**
- Consumes: `plan`, `apply`, the record (Task 3).
- Produces: record entries `merged: [{ file, key: string[], entry, createdKey: boolean }]` (`createdKey` true when install created the array or any parent key), `blocks: [{ file: "AGENTS.md" }]`, `imports: [{ file: "CLAUDE.md", line: "@AGENTS.md" }]`, `created: [<path>]` for shared files that did not exist before.

Rules (spec 5.3, 5.4):
- Each hook piece adds, per element of its `claude` array, under `hooks.<event>` of `.claude/settings.json`: `{ "matcher": <matcher if any>, "hooks": [{ "type": "command", "command": <hook command for its id> }] }`. Also `"Bash(node .xworkflows/mark.mjs:*)"` under `permissions.allow`.
- An entry is present if one is deep-equal, or if one is ours: some `hooks[].command` contains `/.xworkflows/hooks/run.mjs" claude <id>`. Missing entries are appended at the end of the array; keys are created only when absent; existing keys and entries keep their order. Nothing missing: the file is not rewritten. A file that does not parse: exit 1, nothing written.
- `AGENTS.md`: the block is `<!-- xworkflows:start -->\n<templates/AGENTS.md>\n<!-- xworkflows:end -->\n`. Missing file: created with only the block. No block: append it, preceded by `\n` if the file does not end with one, and one blank line. A block whose text differs is replaced in place. Text outside the markers never changes.
- `CLAUDE.md` missing: created as `@AGENTS.md\n`, recorded in `created` and `imports`. Existing `CLAUDE.md` is Task 5.

### Task 5: `install`: questions and files that already exist

**Files:**
- Modify: `bin/xworkflows.mjs`, `bin/xworkflows.test.mjs`

**Interfaces:**
- Consumes: Tasks 3 and 4.
- Produces: record entries `declined: [{ file: "CLAUDE.md", what: "import" }]`, `kept: [<target path>]`, `renamed: { <new target dir or file>: <piece id> }`.

Rules (spec 5.5, 5.6):
- Questions are asked with `node:readline` only when `process.stdin.isTTY`. Otherwise each takes its safe answer and is listed at the end of the output as `answered for you: <question> -> <answer>`.
- Existing `CLAUDE.md` without a line `@AGENTS.md`: ask `Add @AGENTS.md to CLAUDE.md?`. Safe: no, recorded in `declined`. `--yes`: append it as the last line (preceded by `\n` if missing), recorded in `imports`.
- A skill folder or agent file of a piece's id exists and is not recorded: if every file is byte-identical to what install would write, adopt it (record it). Otherwise ask `A skill|agent <id> exists. Keep theirs or install ours as xwf-<id>?`. Safe: keep theirs, recorded in `kept`. `--yes`: install as `xwf-<id>`: folder or file name and the `name:` line change, nothing else; recorded in `renamed`.
- Any other file install would write that exists unrecorded: byte-identical → adopt; else exit 1 before any write, printing `exists and is not ours: <path>`.
- Recorded file whose hash differs from the record: keep it, print `kept (changed locally): <path>  new: <package path>`.
- A rerun honors every stored answer (`declined`, `kept`, `renamed`); `--yes` never flips one; nothing is asked again.

- Produces: one line per check, `ok   <text>`, `warn <text>` or `fail <text>`, then `doctor: <n> fail, <m> warn`. Exit 0 with no `fail`, 1 otherwise, 2 on usage.

Checks, in order (spec 7):
1. Git repository; `installed.json` exists and parses (else `fail not installed` or `fail installed.json does not parse`); Node major ≥ 22; `git --version` answers.
2. Each recorded file exists and is readable (`fail` otherwise); hash differs: `warn changed locally: <path>`; each `kept` path: `warn kept theirs: <path>`.
3. Each `merged` entry is still in its file: deep-equal `ok`; an entry recognized as ours but different: `warn changed locally`; none: `fail`.
4. `AGENTS.md` block text equals the template (`fail` otherwise); `CLAUDE.md` has `@AGENTS.md`, else, when declined: `warn CLAUDE.md does not import AGENTS.md: add the line @AGENTS.md`; when not declined: `fail`.
5. Probe: read the `design-first` command from the installed `settings.json` entry and run it with `spawnSync(command, { shell: true, cwd: root })`, stdin a Claude `PreToolUse` `Write` event (`session_id` fresh, `cwd` root, `tool_input.file_path` `<root>/<paths.specs>/xwf-doctor-probe.md`, `content` `"# probe\n"`). Env: a copy of the current env with `XWORKFLOWS_FREE` and `XWORKFLOWS_RECORD` deleted, `CLAUDE_PROJECT_DIR` = root, `XWORKFLOWS_STATE_DIR` = a new temp folder (removed after). `ok` only when stdout parses and `hookSpecificOutput.permissionDecision` is `deny`. Nothing is written in the project.
6. Always-loaded size: bytes of `CLAUDE.md`, each file it imports with a line `@<path>` (path relative to the importing file, recursively, each file once), and `<memory.dir>/MEMORY.md` if present. Always print `always-loaded: <n> bytes of <budget>`; `fail` above the budget.
7. Print `ok   Claude Code: tested`.
