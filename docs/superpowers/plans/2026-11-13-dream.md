# The `dream` skill, started by hand

Goal: G1

Spec: docs/superpowers/specs/2026-11-13-dream.md

## Global Constraints

- "Las más antiguas primero, hasta el tope"
- "Solo en el reporte"
- "Sí, una vez"
- A run never changes the main branch or the main checkout, and writes nothing outside the branch `dream/<date>` and a temp folder.
- No test calls a model or reads the real sessions of the machine: tests build their own session files in a temp folder and point the script at it.
- A script of the skill runs from the package (`skills/dream/`) and from a project (`.claude/skills/dream/`). It finds the method's shared code (`hooks/core`, `checks`) in both, through `skills/dream/shared.mjs`, and a test runs it from a copy laid out as a project.
- Node standard library only. The design is `docs/design.md` section 7.9: where this plan and the spec are silent, that section rules.

### Batch 1, confirmation at `3aa2f97` and second round

The confirmation left five blocking findings and ten that do not block. All five are in places that already had a finding. This is the second round, the last one allowed: a blocking finding after it goes to the owner with its cause and a design, and no third round follows.

Possible design error in `mask` of `skills/dream/extract.mjs`
- Cause: the mask is a list of spellings of a secret. Each round adds spellings and the list never ends; a value in backticks after "password:" passes.
- Design: judge by line. A line that holds a credential word has every value-like run on the rest of it masked, whatever stands between; one more rule masks long random-looking runs anywhere. This wide rule serves the extract, where a wrong hit costs nothing. At close no note is rewritten by the wide rule: sure shapes (a key of a known form, a private key block) are masked, and a line the wide rule would mask is named, file and line, for the owner to look at before adopting.

Possible design error in `close` of `skills/dream/branch.mjs`, what it may read and write
- Cause: it tests for a link at each file it writes, one test per call; a link in a parent folder is followed. With the memory folder itself a link, close wrote into the owner's real notes folder.
- Design: one helper for every read and write of close: the real path of the target's folder must lie under the worktree's real path. A project whose memory folder is a link cannot run `/dream`, and is told so before it pays.

Possible design error in the reading of the state, `run` of `skills/dream/extract.mjs`
- Cause: the state has one home, the memory folder of the adopted branch, but the extract reads the working folder while `open` starts from the main branch, and a state it cannot read counts as none. A run that waits unmerged is read and paid again with no word.
- Design: the extract asks git for the state at the commit `open` starts from, refuses a state it cannot parse, and reports the `dream/` branches that wait, so the one question to the owner says it.

Possible design error in `decide` of `hooks/core/orchestrator.mjs`, who the rule is for
- Cause: the rule knows the two agents by a fixed name pattern, beside the way the hook already knows an agent of the package (its installed name). A project with its own agent of that name is denied.
- Design: one way only, the installed name from `ctx`.

Possible design error in `decide` of `hooks/core/orchestrator.mjs`, where the run is
- Cause: the rule guesses the run's folder from the temp folder of its own process and reads files itself. With another temp folder than the shell that ran `open`, it denies a correct write with a wrong reason; and `decide` is no longer pure.
- Design: the mark `open` writes is the single source. The hook finds the marked worktrees from the project's own git folder, through `ctx`, and compares real paths.
