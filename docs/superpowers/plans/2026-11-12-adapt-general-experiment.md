# Adapt, general: the experiment (one page)

Goal: G-none yet (no `docs/BUSINESS.md` in this repository until xworkflows
is installed in itself).

Design: `docs/design.md` 8.2 (the split in three) and 10.1 (how it is
judged), owner, 2026-11-12. This is an experiment: a cheap throwaway proof
first, a real build only on the owner's yes.

## Global Constraints

Owner, 2026-11-12:
- The frame stays in code: fixed flow, verified citations, question queue,
  gates, replay with recorded answers. Judgment goes to agents and their
  result is saved in a file the replays reuse: which sentence is a rule (any
  language, docstrings included), which area it belongs to, which patterns to
  look for in this stack, and which group each finding goes to.
- Areas: about 7 universal ones plus up to 4 the agent proposes for the
  project. For group 2, each area agent also returns the exceptions to its
  general rule, each with a citation.
- No example in the instructions comes from the reference project.
- Tuning uses the copy of the reference only, two rounds at most. The exam
  projects are never used to tune; each version goes through the exam once.
- The owner writes no answer key: the owner marks, never drafts.
- Money: only the free credits. Harness with `--api-credits`, 15 USD per run,
  60 in total, ledger passed with `--spend-file`. The cost of the first run of
  each kind is told to the owner before the rest.
- This lane touches only `skills/adapt/`, `agents/mechanism.md`, `proof/` and
  `hooks/core/adapt-*`. `manifest.json` is regenerated by `pack` at merge.
- The exam projects' names never enter a tracked file; everything about them
  lives in git-ignored `docs/proof/private/`.
- If the screen of group 1 passes about 12 rules, or group 2 about 6
  questions, the owner is told how many were left out and why.

## Steps

- B0. The written key, per exam project, before any run: a clone
  (`git clone --no-hardlinks`) without its agent instruction files; an agent
  outside `adapt` extracts the rules those files stated, each with its
  citation. An empty key is reported as empty.
- B1. Baseline: the current version, 3 research-only runs per exam clone.
  Reported without the owner: rules found, empty areas, hits against the
  written key.
- B2. Throwaway proof of the new version, tuned on the reference copy only.
- B3. One pass of the new version through the exam, 3 runs per project. Then
  the owner's blind judgment, once per project: rules of both versions and
  all runs grouped by meaning by an agent outside `adapt`, shown mixed; the
  owner marks correct or invented and adds missing rules in one line each.
  More than about 40 rules: the owner is warned first. Each key rule is then
  looked for in the code («in the code» needs a verified citation, else
  «only in the owner's head»); same for the reference's 10 invariants. Both
  versions side by side, with cost, and a short proposal.
- B4. Before any live interview: the printed screen of group 1 and the
  questions of groups 2 and 3 with their options, for a 5-minute read. The
  interview is measured later: one live, three replays.

## Done when (the owner's list, point 7)

Per project (the reference to tune; exam projects A and B to examine), per
version, 3 runs each, with cost: correct; invented; escaped, split into «in
the code» and «only in the owner's head»; and, when measured, how many
head-only rules the interview wrote and the owner's minutes.

## Review Focus

A key or an exam result leaking into a prompt, a fixture or a tracked file; a
citation that is not verified by a script; a cut of group 1 or 2 that is not
reported; spend outside the ledger.
