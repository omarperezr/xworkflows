# Measure: cost and quality per batch

Goal: G1

## 1. The request, deepened

Request: a development tool that writes, for each batch of a project, one row of numbers: tokens and cost per model and role, risk-review runs, review rounds, fixes that repair an earlier fix, failures found after the seal, and false hook denials; and compares each batch with the batches of the reference project, which ran the prototype of the method. Done: the pilot's five batches are measured against that baseline, and the shares of the read-only diagnosis of 2026-11-15 (spec spend-cut, section 1) come out again within 2 points on the same period of this repository.

Adds:
- A batch is one `--no-ff` merge on the main branch; its time window runs from the merge before it to its own merge, so its design and planning count in it. Batches run one at a time, so the window holds them; other work in the same project inside the window counts too.
- Each assistant message counts once, by its id; cache writes of 5 minutes and of 1 hour are priced apart; the price table carries its date and URL.
- A fix that repairs an earlier fix: the lines a `fix:` commit changes or deletes are blamed, at its parent, on an earlier `fix:` commit of the same batch.
- A failure after the seal: the same blame lands on a commit of an earlier batch. It counts against that batch, with no time limit.
- A false denial: only a judge can tell; the tool lists the denials of the window and stores a judgment it is given.
- The rows hold numbers, branch names and commit ids only, never session text.

Material:
- Session files hold, per assistant message, `message.id`, `message.model`, `timestamp`, `gitBranch` and `usage` with `cache_creation.ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens`; subagent files sit under `<session>/subagents/` with a `.meta.json` holding `agentType` and `model` (grep on this repository's sessions, 2026-11-18). `tested`
- The reference project has 123 merges on its main branch since 2026-10-18, the first day with saved sessions; this repository has 48 (`git log --merges --first-parent main --oneline | wc -l`, 2026-11-18). `tested`
- Hook denials are appended to `xwf-hooks.log` in the state folder, `XWORKFLOWS_STATE_DIR` or the system temp folder (`hooks/run.mjs:17`), one line each with time, session, hook and reason; allows are not logged. `read not tested`
- `docs/measure-tokens.py:19-40` sums tokens per model and stage from session files and prices nothing. `read not tested`
- `proof/trial-lib.mjs:85-108` keeps a spend ledger of the proof harness. `read not tested`

Methods:
- Read the session files Claude Code already writes: works today, no install, every message has its time. Their format is not documented, so a field that disappears stops the tool with one line.

Proof:
- Prices per million tokens (input / output / 5-minute cache write / 1-hour cache write / cache read): Fable 5.2 8 / 40 / 10 / 16 / 0.20; Opus 5.5 4 / 20 / 5 / 8 / 0.20; Sonnet 5.5 2 / 10 / 2.50 / 4 / 0.10; Haiku 5.5 0.10 / 0.50 / 0.125 / 0.20 / 0.01. https://platform.claude.com/docs/en/about-claude/pricing `read not tested`
- The fields of session files have no official documentation. https://code.claude.com/docs/en/monitoring-usage `not confirmed`

## 2. Design

1. `proof/measure.mjs`, Node standard library only, development only like the rest of `proof/`; never installed, never in the manifest.
2. `node proof/measure.mjs --project <path>` reads the project's merges and its session folder (`~/.claude/projects/<path with every / as ->/`), computes every batch since the first saved session, and writes `docs/measure/private/<project folder name>.jsonl` again, one row per batch. A second run gives the same file. It reads the project and writes nothing there.
3. A row: merge commit, branch, window, tokens and USD per model and per agent type (the main session is `main`), risk-review runs, review rounds (reviewer and risk-reviewer runs), commits and changed lines, `fix:` commits, fixes that repair a fix, failures after the seal with the commit and batch they came from, denials of the window, false denials.
4. `--baseline <path>` names the project whose rows are the baseline (it must have been measured). The tool prints, per batch of the measured project, one line per number worse than the baseline's median: USD per 100 changed lines, fixes that repair a fix, review rounds, failures after the seal.
5. Denials: the rows list the denials of the window from the hook log. `--false <time> <reason>` stores a judgment in `docs/measure/private/judged.jsonl`; the row counts the judged ones. The log lives in the temp folder, so a restart can lose it; the row then says `denials: log missing`.
6. Failures after the seal: the tool prints each one with its fix commit and the batch it came from. The main session that runs the tool writes, per failure, one line of where it came from and why under `## Failures after the seal` in `docs/measure/private/<project>.md`; a lesson goes into memory only when it holds in any project, never for one case.
7. `docs/measure/private/` is ignored by git. No tracked file names a project of the owner.
8. Who runs it: the main session of this repository, after each batch the pilot merges, and on demand.
