# Hand-off at the end of each batch

Goal: G1

## 1. The request, deepened

Request: when a batch closes, the main session leaves the next session ready with the least context: a hand-off file that a fresh session loads by itself after `/clear`, and that `/compact` uses as its instructions. The hand-off holds what was done, the owner's recent instructions still in force, and every relevant next task, not only the next one. Done: in batches 2 to 5 of the pilot project the main session's cost per batch falls below batch 1 (6.84 USD, `proof/measure.mjs` split by commit times), and no instruction of the owner is lost between sessions.

Adds:
- A rule to choose `/clear` or `/compact`: `/clear` costs nothing; `/compact` is itself a large request.
- The hand-off points at the plan and the pending list instead of copying them, has a byte cap (it is paid on every turn of the next session), and is ignored when stale.
- Instructions of the owner that bind for good already go into the plan (orchestrate); the hand-off carries only what is not written yet.
- Nothing private enters a tracked file.

## 2. Design

1. **Skill `handoff`.** It writes `.xworkflows/handoff.md` and tells the owner in one line whether `/clear` or `/compact` fits, and why. `orchestrate` invokes it when a batch merges, in place of its step 6; the owner can type `/handoff` at any time. No command named smart-compact.
2. **Content: it points, it does not copy.** First line `main: <full sha of mainBranch when written>`. Then three parts: done (batch, merge sha, result); the owner's recent instructions still in force and not yet written in a plan, a spec or the pending list, quoted; every relevant next task, one line each with its id (plan task or card) and the path of its plan or of the pending list. At most `tokens.handoffBytes` bytes (default 1500), separate from `tokens.sessionStartBytes`.
3. **Clear or compact.** The test: does everything the next session needs already stand written in the plan, the pending list and the hand-off? Yes: `/clear`. No (an owner question still open, a design round half done, a debugging in progress, a nuance that matters and does not fit): `/compact`. In doubt: `/compact`.
4. **Loading.** `.xworkflows/handoff.md` is git-ignored: install adds the line, uninstall removes it. A SessionStart hook with source startup or clear puts the file in the context when it exists, fits the cap, and its first line names the current sha of `mainBranch`; otherwise it adds nothing (over the cap: one line that says so). Nothing is deleted.
5. **`/compact`.** A PreCompact hook prints the hand-off, under the same conditions, so its text becomes instructions for the summary; instructions the owner types are kept as well.
6. **Other hosts.** Codex, Cursor and Gemini have no session-start hook in xworkflows: there the skill also gives the hand-off in the chat, ready to paste into the new session.
7. Everything installed keeps the rules of this project: Node standard library, a pure `decide(ev, ctx)` with its test, manifest pieces with their hash, values from `.xworkflows/config.json`.
